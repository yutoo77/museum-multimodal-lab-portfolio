# UIの仕上げと画面記録

このアプリは科学館職員との相談に使う、単一PC向けの研究用デモです。画面の役割を「資料を取り込む」「保存した資料」「質問する」に絞り、原本との照合と回答の根拠を主操作にしました。巨大なダッシュボードやチャット風の演出ではなく、今の作業・次の操作・資料と出典の対応を先に見せています。

## 変更前に確認したこと

2026-11-14に実Edge / Playwrightで13状態を撮影しました。**画面は実ブラウザ描画ですが、資料・API応答・回答は架空のFake API**です。実モデルの動作実績ではありません。1280×800を基本に、1024×768の取り込み・回答も確認しました。ページ例外は0件で、この2画面には横はみ出しがありませんでした。

白と水色の配色、三つの画面、原本と確認テキストを左右に並べる構成は維持します。改善点は、番号だけのナビゲーション、小さめの補助文字、文字だけで目立ちにくい補助操作、回答後も大きく残る入力欄でした。取り込み空状態の余白はありますが、画面全体の再設計を要するほどの混乱は確認できませんでした。

変更前の13枚と一覧画像はGit管理外の `outputs/portfolio-ui-review/before/` に保存しています。実館資料・通常デモDB・実モデルは使っていません。

## 採用した判断

- 主要な三画面は維持し、ナビの視認性と補助文字の読みやすさを上げる。操作名は日本語で残し、アイコンだけで主操作を説明しない。
- 原本と抽出文の左右照合、回答から該当出典・元資料へ戻る導線を維持する。回答の下に確認可能な根拠を置き、資料の関係を切らない。
- 通常の画面では状態と次の操作を優先し、注意点や処理方式の説明は「使い方」へ分ける。詳細は必要なときに開けるようにする。
- アイコンだけの補助ボタンには日本語の名前とホバー・キーボードフォーカス時の説明を付ける。装飾のためのアイコンは増やさない。

参考にしたのは画面素材ではなく、[Linearの主作業を中心にするナビゲーション](https://linear.app/now/behind-the-latest-design-refresh)、[Notionのワークスペースと補助操作の分離](https://www.notion.com/help/intro-to-workspaces)、[ChatGPT Searchの回答と出典の関係](https://help.openai.com/en/articles/9237897-searching-the-web-with-chatgpt)、[Perplexityの根拠へ進む操作](https://www.perplexity.ai/en-GB/hub/blog/getting-started-with-perplexity)です。アイコンの説明は [WAI-ARIA Tooltip Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/tooltip/) を参考にし、外部サービスの素材や画面をコピーしていません。

変更後の撮影も**実ブラウザ＋架空のFake API**で、実モデル生成のスクリーンショットではありません。1280×800と1024×768の取り込み・回答を含み、撮影中のページ例外は0件でした。全17枚と一覧画像はGit管理外の `outputs/portfolio-ui-review/after/` に保存しています。公開用にはこのうち架空資料だけの画面を選別して掲載します。画面を見やすくしたことは、科学館職員の使いやすさを実証した意味ではありません。

このページと公開用スクリーンショットはUIの視覚・操作導線を示すものです。実モデルの抽出・検索・回答の少数例は [TEST_REPORT.md](../TEST_REPORT.md) に別途記録しています。Fake APIの画面を実モデルの成功例とは扱いません。科学館職員による操作評価、未見資料に対する精度評価、ネットワーク遮断下での実行は、このUI確認の範囲外です。

## 原本照合の最終調整（2026-11-14）

変更前の[原本照合](screenshots/05_review_overview_FAKE.png)と[出典比較](screenshots/10_source_comparison_FAKE.png)では、同じ架空表の数値・単位がプレビュー幅に合わせて縮小され、細部を読むには別タブで開く必要がありました。変更後は画像・PDFの原本側を100～300%で拡大し、スクロール・マウスドラッグ・キーボードで移動、「全体表示」で戻せます。比較文は横に残し、PDFページ移動と原本リンクも維持しました。[実モデル後の比較](screenshots/source-comparison-real-ollama.png)と[150%拡大](screenshots/source-zoom-real-ollama.png)で確認できます。以前のFake API画面と今回の実モデル画面は生成条件が異なり、見た目の厳密な同条件比較ではありません。

1024×768では従来1100px以下で原本と文を上下に積んでいました。今は[画像の確認](screenshots/review-1024-FAKE.png)と[PDF 2ページの出典比較](screenshots/source-comparison-pdf-1024-FAKE.png)で、狭いPC幅でも左右を維持し、横はみ出しがないことを実Edgeで確認しました。この2枚は**架空のFake API/画像で描いた操作テスト画面**であり、PDFの実抽出精度を示しません。900px以下では読みやすさを優先して縦配置に戻します。

補助ラベル、PDFページ表示、確認テキスト、回答本文の文字サイズ・濃さを調整しました。原本リンクは「元画像を開く」「元PDFを開く」と対象が分かる名前にしました。曖昧な質問では「回答案」や「根拠」と誤表示せず、[候補資料の確認（Fake API UI検査）](screenshots/clarification-1024-FAKE.png)として区別します。これはUI状態の操作テストであり、実モデルの回答例ではありません。

最終の6枚の実モデル画面は、空の隔離DBで自作表画像を読み取り、人が修正・登録し、ローカル埋め込み検索・LLM回答・正しい出典へ進んだ操作から選びました。[自動抽出](screenshots/review-raw-real-ollama.png)は「実在」を「実際」と読んだため、[確定文](screenshots/review-corrected-real-ollama.png)は人による修正です。[回答案と出典](screenshots/answer-real-ollama.png)は生成文そのままで、原本の17℃と対応しました。ブラウザーのAPIを偽装せず、PNGを加工せずに撮影しています。実モデル3回の回答・撮影時のテストスクリプト失敗1回・保存資料の保全を含む詳しい範囲は[TEST_REPORT.md](../TEST_REPORT.md)を参照してください。

実画面の可読性と操作経路を確認したのであって、科学館職員による受容性、弱視環境での見え方、全てのPDFや長い資料での使いやすさは未評価です。
