# 技術選定と保留した判断

訪問用デモの目的は、画像・PDF・音声から得た情報を**人が確認してから**検索可能にし、後の質問に根拠を付ける一往復を動かすことです。正確な自動案内システムや学芸員業務の最終仕様を先取りしません。

## なぜ人の承認を索引化の前に置くか

画像モデルの文章は元画像の**解釈**、ASRの文字は発話の**推定**です。モデルが表の行列を取り違えたり、音声の否定や数字を誤認したまま検索に入れると、後の質問で誤った「根拠」に見えてしまいます。そのため、アップロードや抽出の時点ではChunkを作らず、人が元ファイルと照合して明示的に登録した時だけ埋め込みを計算します。確認済み本文の修正・正常に完了した再解析・同名差し替えでは旧索引を無効にします。再解析・再索引の失敗時は、以前の有効な索引を保持する設計です。

一方、承認チェックは**正答率を保証する印ではありません**。現時点で科学館職員・専門家による運用評価はありません。デモで自作資料を自分で確認する操作と、実業務での承認責任は分けます。

## ローカル通信の境界

FastAPI/Viteと専用Ollamaは`127.0.0.1`へバインドし、Ollama URLはloopbackのHTTPを検証します。起動スクリプトが触れるのは自分の11436番サーバーで、既存Ollamaは停止・再設定しません。HTTPクライアントは環境プロキシとリダイレクトを使わず、アプリにクラウドAIへのフォールバックを設けません。初回のpip/npm・モデル取得は別の開発準備であり、資料処理時の外部送信とは区別します。これらは**このアプリのコード上の制約**で、OS全体、ブラウザー、既存Ollamaプロセスの通信遮断を証明しません。端末全体を物理的な閉域とみなすには別の運用確認が必要です。

ローカル専用でもアップロードの拡張子・内容・サイズ、表示名と保存パスの分離、原本のUUID管理を行います。異なる`Origin`または`Sec-Fetch-Site: cross-site`を伴う`POST/PATCH/DELETE`を拒否し、外部Webページからの不用意な操作を抑えます。ただしこれらのヘッダーは**認証ではありません**。LAN公開、共有PCでの多人数使用、実資料の保存、バックアップ・削除ポリシーは今回のデモ範囲外です。今回の準備ではpipによる新アプリ専用環境への導入と、faster-whisperの`tiny`・`base`のユーザーキャッシュへの取得を行いました。これはネット接続を使う**セットアップ**であり、デモ時のASRモデル読込は`local_files_only=True`です。OS全体のセキュリティ設定・ネットワーク設定は変更していません。

## 回答の安全側への倒し方と限界

モデルには確認済みの検索候補だけを送り、根拠がない質問なら空回答を要求します。Backendも候補外ID、空回答、引用に存在しない数値を保留します。候補不足も検索ゲートで保留します。異なる識別番号の資料が強い語句一致で複数候補になる質問は、識別番号等で対象を確認するよう促し、選び切れないままLLMに答えさせません。生成中に参照Chunkが編集・削除・差替えで古くなった場合、返却直前のDB再確認で保留します。ただし、応答送信までを厳密に原子化するものではありません。これらは資料外回答の**一部を抑える**ための検査であり、識別番号のない資料の衝突、対象と値の取り違え、VLMの誤読、自然な文章の意味的誤りを網羅しません。出典カードは人が原本へ戻るための手掛かりです。無確認で来館者に自動回答する用途には使いません。

## 今後の判断に必要な証拠

自作の表画像・テキストPDF・短いWAV各1件で、抽出→テスト操作で修正→登録→質問と原本への出典を確認しました。特に音声の元認識は固有名詞と時刻を大きく誤り、修正前の推定を知識として使わない設計の意義が明確になりました。表の対応関係、別資料の似た数値の取り違え、未知質問の保留、他形式・未見資料への一般化は追加評価が必要です。結果は[TEST_REPORT.md](TEST_REPORT.md)に記し、導入済みモデル一覧だけを性能の根拠にはしません。
